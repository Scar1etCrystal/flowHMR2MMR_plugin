# 让 AI 拿到就能干活（你怎么下指令、要放什么）

这份是给**用插件的人**看的：AI 从哪里看到东西、怎么动手、你们俩怎么对齐，
以及你要做什么。方向箭头怎么摆的细节在 `方向说明.md`；怎么把问题说清楚在仓库的
`docs/反馈问题的方法.md`；AI 侧的工具参数表不在本扩展内（在仓库的 `docs/工具手册_agent.md`）。

---

## 1. AI 从哪进来

| 通道 | 怎么用 |
|---|---|
| **MCP**（推荐给支持 MCP 的宿主） | 宿主（Claude Code / Cursor…）把 `tools/agent_mcp.py` 当 MCP server 起，每次调用转发到本地 socket |
| **命令行** | `<套件>/tools/agent <工具> '<json参数>'`（远程套件，任何目录可用）|
| **Python** | `python tools/agent_client.py <工具> '<json参数>' --pretty` |

AI 连的是 **你正开着的这个 Blender** 里的服务：`127.0.0.1:6207`，JSON-lines，一问一答。

**你的操作**：N 面板 → MoCap Doctor → **Agent 协作** → 「启动服务」。
那一栏同时是你看结果的地方：修复列表、每条的**眼睛**（单独关掉做 A/B）、力度滑块、
参数区、提交 / 撤销 / 清除。

服务默认不开。AI 上来第一件事是 `ping`，没开它会让你去按那个按钮。

## 2. AI 能看到什么

一共 49 个工具，一半是"读"。按**数据来源**分四类，用途完全不同：

| 类别 | 工具 | 看的是 |
|---|---|---|
| **约定类**（开工先跑一次） | `conventions` `get_overview` `describe` | 这份文件的帧号↔视频怎么对应、单位、左右、镜头/视口在角色哪一侧（画面左右是否镜像）、角色这帧面朝哪、哪条腿/胳膊是 IK 还是 FK、场景里已有的标记箭头清单 |
| **快照类** | `get_series` `find_events` `compare` `snapshot` `bake_range` `get_joint_angles` `list_intervals` `validate` | **最初烘焙的原始动作**——修复过之后它也不变 |
| **实时类** | `probe_anatomy` `orient_report` `analyze_motion` `compare_motion` `chain_lag` `slide_report` `ground_report` `effect_check` | **当前可见姿态**（含全部修复）。**修后复测只用这一类** |
| **场景类** | `list_timeline_markers` | **你在时间轴上按 M 放的命名标记**（"就是这一下"），每条附**覆盖那一帧的标注区间** |
| **看图类** | `render_view` | 无头渲一张 PNG（~0.5 s）：绿=标记、红=部位当前方向、蓝=目标 |

`eval_bpy` 是只读的现场求值，兜底用。

**这四类里最要紧的一条规矩**：快照类是"动作原样"，实时类是"你眼睛现在看到的"。
所以"修好了没有"只能用实时类回答——不然就是拿修改前的数据自证。

## 3. AI 能做什么

所有写入都走 **NLA delta strip**，而且是 **preview**：

- **可撤销**：`revert` 一条；**可重写**：`reapply`（同一条轨道换参数，op_id 不变，不堆垃圾 strip）
- **可调力度**：`set_influence`（>1 超量）；面板上就是那条滑块
- **可 A/B**：`ab_toggle` 全部静音/放响，或面板上单条的眼睛
- **先干跑**：`dry_run:true` 支持的工具有一批，先看会改成什么样
- **`commit` 只属于你**——AI 不许调，面板上的「提交」是你按的

一次修复 = 一条 op，记录在案（谁写的、动了哪些骨、哪些帧、能不能重放）。
多条 agent 同时干活时用 `claim` 租约 + `plan_scopes` 分批，撞车会返回 `E_CLAIMED` / `E_STALE`
让后来的人重读再写，而不是闷头覆盖。

## 4. 你们俩怎么对齐

这是整套东西的核心。有五层，从粗到细：

**① 约定一次问清** —— `conventions` 把"这份文件的常识"一次性交给 AI：
帧号怎么对应视频、角色这帧面朝哪、镜头在角色哪一侧。**人看到的和 AI 算的在这里对齐。**

**② 方向词** —— 说方向别说坐标轴（角色会转身，世界 −Y 不是"前面"）：

`朝前/朝后`（角色自己的）、`角色左/角色右`、`朝镜头`、`背离镜头`、`朝视口`、
`画面左/右/上/下`、`朝上/朝下`、`朝脚尖`、`朝<某部位>`。

裸的"左 / 右"会**直接报错**——AI 会问你到底是角色左还是画面左。

**③ 标记箭头（`MCD_*`）** —— 你和 AI 共用的方向定义。你摆的箭头是**权威**：
工具看到合格的标记就以它为准，并在证据里标 `source=marker`。这套包括
掌心 / 脚底 / 膝 / 肘 / 脸 / 胸 / 骨盆七支。做法见 `方向说明.md`。

也可以让 AI 代劳：`markers create` 一次建好（初值从网格/铰链/静止朝向标定），
或者你自己绑好让它 `adopt` 收编。`markers check` 是绑定体检——绑错侧、
顶点父级挂在另一只手、带着关键帧，都会报 error 并说明怎么修。

**④ 标注区间** —— NLA 标注编辑器里的 `planted`（接触）和腾空：
- **planted** 决定脚滑 / 贴地（哪几帧这只脚是踩住的）
- **腾空** 决定跳跃（按视频标：人离地到落地整段）
- 只影响对应步骤，标注编辑器里也只显示那一条轨道

**⑤ 复测口径** —— 每次修完 AI 必须用实时类工具独立复测，并报
**「修前 X → 修后 Y，看 A–B 帧」**。"应该没问题"不算做完；"看到才算数"。

## 5. 你要做什么

### 开工（一次）

1. 打开工作文件 → N 面板 → Agent 协作 → **启动服务**
2. （可选，但强烈建议）让 AI 先跑一次 `conventions` 和 `get_overview`——
   它就知道这份文件的帧号、左右、镜头方位、哪些骨有效
3. 朝向类的活儿，先让 AI `markers check`；有你自己摆的箭头就会被收编，
   没有就 `markers create` 建一套，你在视口里扫一眼

### 提需求：一句话

```
<帧段> <部位> <看到的问题> → <想要的样子>
```

| 你说 | AI 得到 |
|---|---|
| `149-223 右手手心朝镜头` | 帧段 + 部位 + 方向目标 |
| `505-570 食指别弯那么狠` | 帧段 + 部位 + 程度 |
| `300 附近左脚踩地打滑` | 大概位置也行，AI 自己找窗口边界 |

帧段 = **要生效的区域**，AI 会自动两端各外扩几帧做过渡。
一句话一件事，多件事分多条说。

### 要放哪些标记

| 你想表达 | 放什么 | 放哪 / 注意 |
|---|---|---|
| 某个部位**长期**的朝向标准 | **`MCD_palm.L` 这类部位箭头**（7 支：掌心 / 脚底 / 膝 / 肘 / 脸 / 胸 / 骨盆） | 让 AI `markers create`，或自己绑好让它 `adopt`；做法见 `方向说明.md` |
| **这一条修复**要平行于某方向 | **`mcd_dir_*` 箭头** | 面板上那条修复的 **＋** 按钮放在 3D 游标处，转到想要的方向 |
| **这一条修复**要指向某位置 | **`mcd_aim_*` 小球** | 面板那条修复的 **靶心** 按钮 |
| 想让膝盖/肘**朝某个空物体转**（物体可以随便拖） | **随便一个空物体**（小球、箭头都行） | 跟 AI 说"膝盖朝 `<物体名>` 转"。**只想要某个方向的转动就说清是哪个轴**，例："只转 Z，不用管高低差" |
| 方向**逐帧在变** | 给上面任何一支**打关键帧** | 目标方向就逐帧跟着走 |
| 哪几帧脚是踩住的 | 标注编辑器 → **左脚 planted / 右脚 planted** | 决定脚滑 / 贴地 |
| 哪几帧人离地 | 标注编辑器 → **腾空区间** | 按视频标整段（离地到落地） |
| 哪几帧在做手部动作 | 标注编辑器 → **左手区间 / 右手区间** | 手部预检用 |
| **你指"就是这一下"** | 时间轴 **M 键 marker**（按 M 放，起个名字） | AI 用 `list_timeline_markers` 读得到，还会带上那一帧的标注区间；比在消息里打帧号准，而且存在文件里不会丢 |

**不需要**你放坐标轴、量角度、查骨名。方向交给箭头，帧号交给标注，剩下的 AI 自己算。

⚠ 两套箭头**别互相改名**：`MCD_*` 是全局共用的部位定义；`mcd_dir_*` / `mcd_aim_*` 只服务你正在调的那一条修复。

### 帧号怎么算

- AI 用的就是 **Blender 时间轴帧号**，`frame_range` 两端都含。
- **视频 / pkl 的第 i 帧（从 0 数）= Blender 第 i+1 帧**。
- 你给的帧段 = **要生效的区域**；AI 自动两端各外扩几帧做过渡，复测报的「看 a–b 帧」是去掉过渡后的**有效区**。

### 一个小陷阱：`朝镜头` 用的是默认相机

`朝镜头` 按 `scene.camera` 算，而你可能在看别的视口。要"朝我正在看的这个方向"就说 **`朝视口`**。

### 修完之后你怎么看

1. 视口里对着**视频对应帧**看**实际网格**（不要只看数字）
2. 面板上逐条按**眼睛**做 A/B
3. 参数不满意直接拖那条下面的滑块——**同一条改参数不要重新提一遍需求**，拖完自动重写
4. 还不对就带帧号再说一次：`还是不对，F182 这只手应该手心朝前`

### 有一个"机器猜不准、你一眼就对"的：脚底朝向

**脚底法线**（"脚底朝哪"）是唯一一个 AI **算不准**的方向：它靠脚踝、前掌、脚尖三点定平面，
而**厚底靴的踝比鞋底高 ~5.5cm**，这三点几乎躺在脚的同一个竖直切面里，算出来的"脚底法线"
会**歪到侧面**（实测偏 **79°**）。我们试过用靴子网格自动标定，还是差 60–70°。

**所以脚底这一项交给你**：让 AI 跑一次 `markers create` 建出 7 支部位箭头，然后
**你挑一个脚踩平的帧，把 `MCD_sole.L` / `MCD_sole.R` 转成箭头垂直朝下**（从鞋底穿出去）。
之后 AI 全部以你转的箭头为准，`probe_anatomy` 会报 `sole_source: "marker"`。

- `markers check` 会提示"`MCD_sole` 与几何定义差 79°"——**这是预期的**，那正是让你拍板的提示，不是错误。
- 现在文件里的 `MCD_sole.L/R` 已经摆正过了（仰角 −86.6°），换文件时记得重做一次。
- 其它部位（掌心 / 膝 / 肘）仍有网格/铰链标定，但也要肉眼确认；你的部位箭头优先于自动估计。

## 6. 为什么这样设计能省时间

三个机制，专门用来"不让 AI 把时间花在学工具上"：

1. **读工具直接吐出写工具的参数**——
   `probe_anatomy` 返回 `hold_pose_args`（可直接展开进写调用）；
   `analyze_motion` 返回 `suggest.<工具>.args`；
   `ground_report` 返回 `fix_ground_args`；`slide_report` 的 flagged 行直接带 `foot_lock` 参数。
   **先诊断，参数自己就出来了，不用猜。**
2. **一次调用拿全约定** —— `conventions` 替代十几轮"这个文件里朝前是哪个方向"。
3. **每类问题一个固定剧本** —— 抖、朝向、打击感、脚滑/穿地、复制镜像、
   预备/跟随/过冲、重叠/改节奏，各有固定流程和验收指标，AI 不需要自己发明方法。
4. **用户标的那一下直接可读** —— `list_timeline_markers` 把你在时间轴上按 M 放的命名标记连同覆盖那一帧的标注区间一起交给 AI，它不用再问"你说的是哪一帧"。


配套还有一页 `05_quickstart_weak_model.md` 给能力较弱的模型，每条命令都在测试文件上跑通过。
